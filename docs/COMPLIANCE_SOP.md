# 컴플라이언스 운영 SOP (Standard Operating Procedure)

> 1인 기업 운영 기준. 대표(DPO 겸직)가 직접 수행하거나 위탁할 절차를 시간 흐름·사건 흐름으로 정리.
>
> 본 문서는 **"법적 고통을 받지 않기 위해 반복적으로 해야 하는 일"** 의 체크리스트.
>
> AI 기본법 §34 고영향 AI 책무의 이행 현황(조치별 구현 근거)은 [AI_RISK_MGMT.md](AI_RISK_MGMT.md) 참고 — 본 SOP 의 §2-2(점수분포 모니터링)·§2-3(법령 모니터링)·§3-1(침해사고) 이 그 위험관리방안의 운영 절차에 해당.

## 마스킹 정책 (2026-05-26, 폴백 예외 2026-07-11)

`lib/mask.ts` 의 자동 마스킹 동작은 항상 적용. 모든 LLM 호출이 Vertex AI 서울 리전(asia-northeast3) 으로 통합되어 AI 단계의 국외이전은 발생하지 않음.

**도쿄 폴백 예외 (2026-07-11)**: 서울 장애(429/503) 시 **프롬프트에 개인정보가 전혀 없는 호출만** `allowFallback: true` 로 도쿄(asia-northeast1)에 폴백한다 — MCQ 생성/번역·JD 체크리스트·법인 매칭·공고 URL 임포트(담당자 연락처 `maskContacts` 마스킹 후) 5곳. 개인정보가 없으므로 §28의8 국외이전에 해당하지 않아 "AI 단계 국외이전 없음" 고지와 모순되지 않는다. **개인정보(마스킹 이력서·면접 대화 포함) 호출의 폴백은 동의서·처리방침에 §28의8 국외이전 고지(5항목)를 반영하기 전까지 금지.**

### task별 마스킹 책임

| task | LLM 위치 | 마스킹 법적 의무 |
|---|---|---|
| `screening`, `interview`, `interviewEval` | Vertex AI 서울 (asia-northeast3) | 🟡 **§4의3 평가 금지 항목 필수.** 그 외 (이름·전화·이메일·주소·회사명) 는 모범관행 — 누락 시 운영 개선 항목. 면접 중 후보자 자가 발화도 마스킹 유지 (chat/route.ts) — §4의3 평가 금지 항목 노출 방지 목적 |

### §4의3 평가 금지 항목 (반드시 마스킹)

채용절차의 공정화에 관한 법률 §4의3:
- 성별·나이·출신지(본적·출생지)·가족관계·혼인·종교·정치 견해
- **출신 학교명·학교 서열** (학벌 — 고용정책기본법 §7 차별 금지)
- 부모·형제의 직업·학력·재산
- 신체 조건 (키·체중·외모·장애 여부 — 직무 직접 필요한 경우 제외)

→ 이 항목들은 **screening/interview 어느 단계든 마스킹 누락 시 법적 위반**. 사전 미등록 회사명·신조어 학교명 등 잔존 시 우선 보완.

**학력 수준·전공은 평가 허용 (2026-05 정책)**: 본인의 최종학력 수준(학사/석사/박사)·전공은 채용절차법 수집 금지 항목이 아니며, 직무 관련성(고용정책기본법 §7 "합리적 이유")이 있을 때 JD 매칭에 사용 가능. `lib/education-extract.ts` 가 업로드 시 추출 → `buildScreeningPrompt` 에 **학력·전공만** 전달(출신 학교명 제외). 단, JD 가 특정 학력/전공을 요구할 때만 가·감점, 무관하면 반영 금지.

### 사용자·법무 대상 표현 통일

- ✅ "AI 평가 시 식별 가능한 정보를 자동 마스킹 처리하여 LLM 에 전달합니다"
- ✅ "사전·정규식 기반 자동 처리로, 신규 학교명·회사명·변형 표기는 잔존 가능성 있음"
- ❌ "개인정보는 절대 LLM 에 전달되지 않습니다" (100% 보장 표현 금지)
- ❌ "모든 개인정보가 차단됩니다" (절대 표현 금지)

### 신규 LLM 호출 추가 시 체크

1. task 파라미터 명시 (`generateJSON(prompt, { task })`)
2. 입력 텍스트가 `maskText` 거친 텍스트인지 확인 (resume_masked_text 또는 sanitize)
3. interview·면접평가 계열이면 추가로 면접 중 사용자 발화 마스킹 필요한지 검토
4. 모든 task 는 Vertex AI 서울 리전 사용 — 직접 API(미국)로 우회하지 말 것. 우회 시 §28의8 동의 항목을 다시 추가해야 함.
5. `allowFallback: true` (도쿄 폴백)는 프롬프트에 개인정보가 **전혀** 없는 호출만 — 위 "도쿄 폴백 예외" 기준. 개인정보 호출에 켜려면 동의서·처리방침 개정이 선행돼야 한다.

## 0. 운영 전 (1회성) — 사업자등록 직후 즉시

이 항목들은 첫 유료 고객을 받기 **전에** 마쳐야 합니다. 미완 상태로 영업 시작 시 후행 리스크.

### 0-1. 사업자등록

- 홈택스 → 사업자등록 (개인사업자 즉시발급)

### 0-2. 통신판매업 신고

- 정부24 → 통신판매업 신고
- 필요: 사업자등록증 + 구매안전서비스 이용확인증
- 등록면허세 4만 5천원/년
- 결제 받기 시작하는 순간 의무 (전자상거래법 §12)

### 0-3. Google / Vercel / Turso DPA 서명·보관

| 업체 | 절차 | 보관 위치 |
|---|---|---|
| Google Cloud (Gemini API) | Google Cloud Console → 결제 활성화 시 Data Processing Addendum 자동 수락 | `legal/dpa/google.pdf` |
| Vercel | vercel.com/legal/dpa 다운로드 → 서명본 회신 → 양방 서명본 수령 | `legal/dpa/vercel.pdf` |
| Turso | sales@turso.tech 에 DPA 요청 | `legal/dpa/turso.pdf` |

`legal/dpa/` 폴더는 `.gitignore` 에서 트래킹하되 민감 정보는 제외. 보호위 점검 시 즉시 제출 가능 상태 유지.

### 0-4. 개인정보보호 손해배상책임보험 견적

- 가입 시점: 첫 유료 고객 계약 직전
- 추천 견적처: 메리츠화재 / DB손보 / 한화손해보험 (B2B SaaS 특화 상품)
- 권장 한도: 1억원 / 연 보험료 30~50만원 예상
- PIPA §39의9 — 매출 5천만원 + 정보주체 1000명 이상 시 의무

## 2. 분기마다 (3개월)

### 2-1. 무작위 고객사 동의 취득 실태 확인

채용기업이 우리 약관 §5 의 동의 취득 의무를 실제로 이행하는지 표본 점검. 위반 패턴이 보이는데도 우리가 방치하면 **공동책임**으로 전환됩니다.

절차:
1. `audit_logs` 에서 분기 내 `candidate.upload_with_consent` 가 가장 많은 법인 5곳 추출
2. 각 법인에 메일 발송 (템플릿 §2-1-A)
3. 답신: 공고 상세 내용(본문)의 AI 평가 안내 문구 캡처 또는 자체 지원폼 동의 화면 캡처
4. 응답 7영업일 이내. 무응답·거부·위반 적발 시:
   - 1차: 시정 요청 + 2주 유예
   - 2차: 계정 정지 (`POST /api/admin/orgs/[id]/suspend`)
5. 결과는 `legal/quarterly-audit/YYYY-QN.md` 에 기록

## 3. 사건 발생 시 (이벤트 트리거)

### 3-1. 침해 사고 (Data Breach) — 72시간 룰

**발견 즉시 다음 시간계산 시작 (개인정보 보호법 §34).**

| 시점 | 행위 |
|---|---|
| 발견 즉시 | 침해 범위 격리 (감염된 키 폐기, 노출 데이터 식별). 감사 로그 export. |
| 24시간 이내 | 영향 범위 추정 (정보주체 수·항목) |
| 72시간 이내 | 개인정보보호위원회 신고 (privacy.go.kr) + 정보주체 통지 (이메일) |
| 5영업일 이내 | 재발 방지 대책 수립 + 보호위에 추가 보고 |

신고 양식: privacy.go.kr → "민원/신고" → "개인정보 유출 신고". 1000명 이상 영향 시 한국인터넷진흥원(KISA)에도 통지.

### 3-2. 자동화 의사결정 이의제기 접수

후보자가 `/interview/[token]/appeal` 또는 메일로 이의제기:

1. `appeal_logs` 자동 row 생성 + DPO 알림 메일
2. **7영업일 이내** 답변 의무 (§37의2)
3. 응답:
   - AI 평가 기준 설명 (사전공개 페이지 인용)
   - 인적 검토 결과 (채용 담당자가 다시 검토했음을 확인)
   - 필요 시 평가 재실행 또는 일반 채용 절차 안내
4. `/admin/audit` 에서 응대 결과 status 업데이트 (`reviewed` → `resolved` 또는 `rejected`)

### 3-3. 정보주체 권리 요청 (PIPA §35~§37)

후보자가 자신의 정보 열람·정정·삭제·처리정지를 요청:

- 셀프 채널: `/interview/[token]/me` 로 안내
- 메일 요청: 본인 확인 (이메일 인증) 후 10일 이내 처리
- 거부 사유 있으면 (법적 보존 의무 등) 사유 명시 회신

### 3-4. 인권위 진정 / 채용 차별 신고

- 진정 접수 통지 받으면: 해당 후보자의 전체 평가 기록 + 인적 검토 기록 + 분기 모니터링 결과 export
- 즉시 변호사 자문 (개인정보·노동 분야)
- 응대 자료는 **차별 입증의 반대 증거** 로 구성: AI 평가에서 §4의3 항목이 제외됐다, 최종 결정은 사람이 했다, 분기 모니터링 결과 통계적 차별 패턴 없다

### 3-5. 보호위 자료 제출 요구

자료 제출 요구를 받으면 7~14일 시한 부여됨. 다음을 즉시 export:
- `audit_logs` 해당 기간
- `consent_logs` 해당 후보자
- DPA 사본 (Google/Vercel/Turso)
- 분기 모니터링 기록
- 처리방침·이용약관 버전 이력

## 6. 변호사·외부 자문 트리거

다음 사건이 발생하면 즉시 외부 자문 권장:

1. 침해 사고 발생 (3-1)
2. 인권위 진정 통지 (3-4)
3. 보호위 조사·자료제출 요구 (3-5)
4. 민사 소송·내용증명 수신
5. 매출 5억 돌파 (PIA 대상 여부 검토)
6. EU 또는 미국 지원자 발생 (GDPR / AI Act 적용 검토)

추천 자문처 (1인 기업 친화):
- 법무법인 율촌·태평양·세종 등의 IT·개인정보 팀 (비용 부담 큼)
- 개인 변호사 (스타트업 자문 경험) — 시간당 25~40만원
- 개인정보보호위원회 무료 컨설팅 (privacy.go.kr → 자율규제)
- KOSA(소프트웨어산업협회) 법률 자문 (회원사 무료)
