# 모바일 UI/UX QA 분석 리포트

> 작성일 2026-06-01 · 작성: QA · 대상: 이번 모바일 대응 작업 (NavBar 햄버거 + 주요 화면 반응형)
> 기준 뷰포트: 375×812 (iPhone), 360×800 (Android). 브레이크포인트 `sm = 640px`.

## 0. 테스트 방법 & 한계

- **정적 분석 + 코드 리뷰 기반**. 실기기/에뮬레이터 라이브 테스트는 **미수행** — dev 서버가 포트 3003 점유 중이라 프리뷰 전용 서버 기동 불가(프로젝트 규칙상 3003 고정).
- 따라서 아래 결함은 **코드 근거 기반 추정**이며, ⚠️ 표시 항목은 실기기 확인 필요.
- 컴파일/타입: `tsc --noEmit` 통과.

## 2. 기능(Functional) 결함

### F-1 [P2] 햄버거 메뉴 — 포커스 트랩/초기 포커스 없음
- `role="dialog" aria-modal="true"` 선언했으나 **열릴 때 포커스가 패널로 이동하지 않고**, Tab 이 배경 요소로 빠져나감. 배경에 `inert`/`aria-hidden` 미적용.
- 영향: 키보드/스크린리더 사용자. 모바일 비중은 낮지만 a11y 준수 항목.
- 위치: `app/components/NavBar.tsx` `MobileMenu`.
- 권장: 열릴 때 닫기 버튼에 `focus()`, 배경 `aria-hidden`, 간단 포커스 루프.

### F-2 [P3] 햄버거 메뉴 — 라우트 동일 경로 클릭 시 닫힘 의존
- 닫힘 트리거: 오버레이 클릭 / X / Esc / `currentPath` 변경. **현재 페이지와 같은 메뉴를 누르면** pathname 불변이라 `useEffect([currentPath])` 가 안 돌아 패널이 안 닫힐 수 있음. ⚠️ 실기기 확인.
- 권장: `Link onClick` 에서도 `setOpen(false)` 호출.

### F-3 [P3] 후보자 상세 액션바 — 가로 스크롤 발견성
- 버튼 4개를 한 줄(`flex-nowrap overflow-x-auto`)로 배치. 폭 부족 시 가로 스크롤이지만 **스크롤 가능 표시(그라데이션/화살표)가 없어** 일부 버튼이 잘려 안 보일 수 있음. ⚠️ 360px 기기 확인.
- 위치: `app/candidates/[id]/page.tsx` StagePanel.

### F-4 [P3] 관리자 카드 — 편집/관리자이전 기능은 모바일 미노출
- `/admin/orgs` 모바일 카드에 충전/환불/정지·재개만 제공 (요구사항대로). 단 법인명·도메인 **인라인 편집**, **관리자 이전** 은 데스크톱 전용. 의도된 범위이나 문서화 필요(사용자에게 "그건 PC에서").

## 3. UI 결함

### U-1 [P2] 터치 타깃 크기 미달 (광범위)
- 다수 액션 버튼이 `text-xs px-2.5 py-1` / `px-3 py-1.5` → 실측 높이 **약 26~30px**. WCAG 2.5.5 / 모바일 가이드라인 **44×44px** 미달.
- 해당: 후보자 상세 액션, `/admin/orgs`·`/admin/users`·`/org/members` 카드 버튼.
- 권장: 모바일 한정 `min-h-[40px]` 또는 `py-2` 상향(데스크톱 밀도 유지하려면 `sm:` 분기).

### U-2 [P3] 패널 하단 안전영역(safe-area) 미반영
- 햄버거 패널 `h-full`, 하단 로그아웃 `p-4`. iOS 홈 인디케이터/제스처바와 겹칠 수 있음.
- 권장: 패널/하단에 `pb-[env(safe-area-inset-bottom)]`.

### U-3 [P3] 좌우 여백 일관성
- 전환 화면은 `px-4 sm:px-6` 적용. **미전환 화면**(`/account`, `/org/tokens`, `/admin/metrics`, `/admin/dashboard`, `/admin/audit`, `/admin/candidates`, `/jobs/[id]/report`, `/jobs/[id]/compare`, `/jobs/[id]/edit` 본문)은 여전히 `px-6` → 모바일에서 좌우 여백 과다/콘텐츠 협소.

### U-4 [P3] 공고 상세 헤더 액션 다수 시 줄바꿈 밀도
- 헤더 버튼(공유/1차일정/리포트/수정/삭제)을 모바일에서 `flex-wrap` 처리 → 5개가 2~3줄로 쌓임. 동작엔 문제없으나 시각적으로 무거움. (드롭다운 "⋯ 더보기" 통합 고려 — P3.)

## 4. UX 결함 / 개선점

### X-1 [P2] "데스크톱 전용" 처리의 불일치
- 같은 "PC에서 하세요" 의도인데 처리가 **3가지로 혼재**:
  1. 안내문 표시 (`/jobs/new`, `/jobs/[id]/edit`, `/org/smtp`)
  2. 완전 숨김 (공고 상세 내 이력서 업로드 — 아무것도 안 보임)
  3. 진입 버튼 숨김 (대시보드/목록의 "새 공고")
- 결과: 모바일 사용자가 "새 공고"를 메뉴에서 찾다 못 찾고, `/jobs/new` 직접 진입(북마크 등) 시에만 안내문을 봄. **일관된 멘탈 모델 부재.**
- 권장: 원칙 1개로 통일 — "진입점은 숨기되, 직접 URL 진입 시 안내문" (현 상태와 유사하나 업로드 영역도 **빈 화면 대신 짧은 안내문** 권장 — 빈 공간은 '버그'로 오인됨).

### X-2 [P3] 업로드 영역 완전 숨김 → 레이아웃 공백
- 공고 상세 모바일에서 동의게이트+업로드가 통째로 사라져, 펀널과 후보자 탭 사이 흐름은 자연스러우나 **"여기서 뭘 못하는지" 피드백이 없음**. (X-1 권장과 연결)

### X-3 [P3] 가로 스크롤 영역 일관성
- 펀널(전형 단계), 후보자 액션바, 데스크톱 테이블(카드 대신 노출되는 일부) 등 가로 스크롤이 여러 곳. 스크롤 affordance 표준화(끝단 페이드) 권장.

### X-4 [info] 알림 벨 + 햄버거 동시 노출
- 모바일 헤더에 벨/햄버거 공존은 적절. 단 벨 드롭다운(360px)과 햄버거 패널이 **둘 다 열릴 수 있음**(상호 배타 처리 없음). 충돌 시 시각 혼란 가능 — 낮은 빈도.
